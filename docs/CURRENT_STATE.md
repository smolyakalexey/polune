# Polune — текущее состояние

Обновлено: 23 августа 2026.

## Что работает

1. Пользователь выбирает одно из 61 бытового дела.
2. Reveal перебирает будущие даты и приводит к одному рекомендованному дню.
3. Результат показывает дату, фазу Луны, вердикт, практический совет и индекс совпадения.
4. Строка процента открывает прозрачное объяснение двух факторов расчёта.
5. Компактный календарь показывает ближайшие 14 дней; раскрытый — оставшуюся часть текущего и следующий месяц. Прошедшие даты скрыты.
6. Результат можно отправить и сохранить в календарь: уверенно определённая платформа получает прямое действие Apple/Google, неоднозначная — выбор; ручное предпочтение запоминается локально.
7. Данные рождения вводятся на одном экране: маска даты, автоматически определённый знак, маска времени и место рождения.
8. После сохранения на результате остаётся редактируемая строка с введёнными данными и честной пометкой, что они пока не влияют на индекс.
9. Диапазоны календаря проверяются отдельно от интерфейса: 14 дней от московского «сегодня», затем ровно текущий и следующий месяц без восстановления прошлых дат из URL.

## Что важно не переобещать

- Методика 0.6 — символический индекс, а не вероятность события.
- Данные рождения пока не меняют результат.
- Место рождения только проверяется по формату и сохраняется локально. Для реального использования нужны координаты и часовой пояс из проверяемого геокодирования.
- Базовый результат не требует аккаунта.

## Текущий продуктовый фокус

1. Подключить реальный расчёт натальных положений, перепроверить вклад Асцендента и повторить двухлетнюю симуляцию до изменения интерфейса.
2. Подключить геокодирование места рождения.
3. Проверить фактический импорт `.ics` и форму Google Calendar на физических устройствах.
4. Проверить reveal, календарь и `.ics` на физических iPhone/macOS Safari.
5. Собрать внешний контрольный срез только по методике 0.6.

Кандидат `0.7p` уже имеет чистый модуль без UI: дата даёт фактор натального Солнца, примерное время с местом добавляет Луну, точное время с местом — Асцендент. Все видимые даты двух месяцев должны пересчитываться, но автоматическая рекомендация остаётся в ближайшем 14-дневном окне. Дома рассматриваются отдельно для будущей расширенной версии.

Первичная симуляция 2026–2027 по всем 61 делам показала смену рекомендации в 33,3% окон для уровня даты, 43,6% для примерного времени и 44,0% для точного. Точное время нельзя делать обязательным: по текущей сетке оно заметнее меняет индекс и цвет, но почти не увеличивает частоту смены самой даты относительно примерного времени.

## Проверка изменений

- `node --test tests/*.test.mjs`;
- targeted ESLint для изменённых файлов;
- `vinext build`;
- браузерная визуальная проверка только по явному запросу или при сверке с макетом;
- публикация только по явной команде пользователя.
