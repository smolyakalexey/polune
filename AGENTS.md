# Контекст проекта для Codex

## Продукт

Polune — мобильный веб‑сервис для быстрого выбора даты небольшого бытового действия. Главная формула:

> Выбери дело → получи три подходящие даты → пойми объяснение → запланируй.

Основная аудитория первой проверки — русскоязычные женщины 25–44 лет, которые иногда смотрят лунные календари, но не хотят разбираться в сложной эзотерике.

## Цель MVP

Новый пользователь без регистрации должен менее чем за 30 секунд:

1. выбрать намерение;
2. увидеть ближайшие подходящие даты;
3. понять, почему дата рекомендована;
4. сохранить или отправить результат.

## Продуктовые принципы

- Query-first: сначала намерение пользователя, а не календарь.
- Моментальная польза: регистрация и дата рождения не нужны до первого результата.
- Спокойный тон: никаких угроз, фатальности и категоричных запретов.
- Прозрачность: отделять астрономический факт, традиционную интерпретацию и практический совет.
- Одна основная задача на экран; не превращать MVP в энциклопедию.
- Важные медицинские, финансовые и юридические решения находятся вне продукта.

## Границы первой версии

В MVP нужны:

- 5–7 низкорисковых намерений;
- сегодня, завтра и ближайшие 14 дней;
- одна последовательная система правил;
- короткое объяснение;
- сохранение и шаринг;
- один вопрос обратной связи после действия;
- аналитика ключевой воронки перед внешним тестом.

Пока не нужны:

- натальная карта;
- AI‑чат общего назначения;
- Таро, медитации и гороскопы;
- социальная сеть;
- маркетплейс экспертов;
- сложная регистрация;
- нативное приложение;
- подписка до подтверждения повторного использования.

## UX и визуальная система

- Проектировать mobile-first, затем проверять desktop.
- Использовать Mobbin MCP до заметного редизайна: искать паттерны выбора даты, рекомендаций, планирования, доверия и объяснимости.
- Mobbin — источник паттернов, а не шаблон для копирования одного продукта.
- Сначала улучшать иерархию, сценарий и понятность; декоративный polish — после.
- Избегать клише эзотерических продуктов: тяжёлого фиолетового космоса, золотых рамок, псевдонаучности и визуальной тревожности.
- Не добавлять emoji и самодельные SVG вместо нормального набора иконок.
- Поддерживать клавиатуру, заметный focus, достаточный контраст и touch-target не меньше 44 px.

## Работа с Mobbin

Перед изменением основного сценария искать несколько классов референсов:

- date picker и date recommendation;
- wellness daily guidance;
- weather quality/comfort score;
- fertility and cycle calendars;
- habit planning and reminders;
- booking confirmation and calendar save;
- explainable recommendations and trust cues.

Для каждой итерации сначала сформулировать найденные паттерны и только потом менять код.

## Технический контекст

- Next.js/React через Vinext и Vite;
- основной сценарий находится в `app/page.tsx`;
- стили находятся в `app/globals.css`;
- сложного бэкенда и базы данных пока нет;
- публичная версия связана с Sites через `.openai/hosting.json`;
- не добавлять инфраструктуру, авторизацию или базу без подтверждённой продуктовой необходимости.

## Проверка изменений

После значимых изменений:

1. запустить `npm run lint:local`;
2. запустить `npm run build:local`;
3. проверить основной сценарий в браузере на мобильной и desktop-ширине;
4. проверить выбор намерения, смену даты, сохранение и шаринг;
5. визуально проверить переполнение, отступы, контраст и focus;
6. перед публикацией показать изменения пользователю.

## Метрики теста

- 20%+ посетителей получают результат;
- 8%+ сохраняют дату или включают напоминание;
- 25%+ возвращаются за вторым намерением в течение 30 дней;
- 3%+ проявляют подтверждённый интерес к платному календарю;
- отдельно отслеживать выбор намерения, просмотр результата, другую дату, сохранение и шаринг.

## Рабочий стиль

- Делать маленькие проверяемые итерации.
- Не расширять функциональность без явной гипотезы.
- Сохранять существующие пользовательские изменения.
- Перед крупной перестройкой объяснять компромисс и показывать визуальное направление.
- Создавать Git‑коммит после законченного и проверенного этапа.

## Исследование Polune v2

- Ветка `codex/product-v2-exploration` предназначена для развития второй версии без изменения публичного `main`.
- Общий результат остаётся мгновенным и доступным без регистрации.
- Персонализация проектируется как добровольный второй слой после первой пользы.
- Аккаунт нужен для сохранения профиля, истории, длинного календаря и синхронизации, а не для искусственной блокировки базовых действий.
- Результат строится по модели `эмоциональный вердикт → практический совет → как посчитали`.
- Атмосферность и чистота развиваются вместе; сильный reveal проигрывается только после нового запроса.
- Светлая и тёмная темы должны быть одной семантической системой с системным значением по умолчанию.
- Полный план и границы находятся в `docs/PRODUCT_V2.md`, `docs/ROADMAP_V2.md` и `docs/TODO_V2.md`.
